# Отчёт по результатам анализа Kubernetes Audit Log

## Подозрительные события

1. Доступ к секретам:
   - Субъект: system:serviceaccount:secure-ops:monitoring
   - Действие: секрет default-token в namespace kube-system
   - Оценка: Сервисный аккаунт без явных прав попытался получить доступ к чувствительным данным, что может указывать на попытку эскалации привилегий или компрометацию.

2. Привилегированные поды:
   - Субъект: admin или текущий пользователь kubectl
   - Действие: создан pod privileged-pod с параметром securityContext.privileged: true
   - Оценка: Такой контейнер получает практически полный доступ к хостовой системе и нарушает принцип наименьших привилегий.

3. Использование kubectl exec в чужом поде:
   - Субъект: admin или текущий пользователь kubectl
   - Действие: выполнен exec в pod coredns из namespace kube-system для чтения файла /etc/resolv.conf
   - Оценка: Доступ к workload-поду без необходимости может использоваться для расследования или компрометации, хотя в данном случае команда не завершилась успешно из-за отсутствия нужных утилит.

4. Создание RoleBinding с правами cluster-admin:
   - Субъект: admin или текущий пользователь kubectl
   - Действие: сервисному аккаунту monitoring был предоставлен доступ cluster-admin
   - Оценка: Это дает полный контроль над кластером и значительно повышает риск дальнейшей компрометации.

5. Удаление audit-policy.yaml:
   - Субъект: admin с флагом --as=admin
   - Действие: удаление файла audit-policy.yaml на узле minikube
   - Оценка: Критично с точки зрения видимости событий безопасности. Удаление или изменение конфигурации аудита может привести к утрате контроля над последующими инцидентами.

## Вывод

Анализ показывает наличие нескольких серьёзных нарушений в модели безопасности кластера: избыточные права RBAC, возможность запуска привилегированных контейнеров и недостаточные ограничения доступа к чувствительным ресурсам. Для снижения риска необходимо ужесточить RBAC, запретить запуск privileged-контейнеров через admission controllers, ограничить доступ к секретам и обеспечить защиту конфигурации аудита. Дополнительно целесообразно применить сетевые политики и вести регулярный контроль привилегированных операций.
